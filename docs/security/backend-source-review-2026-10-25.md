## Detailed findings

### F01 SSE disconnect cancellation interrupts slot release

**P2 · Unresolved · Earlier FastAPI pass 1**

Location: [controller/conversations_controller.py:395](../../back-end/controller/conversations_controller.py#L395).

Chat and resume stream cleanup awaits Redis-backed limiter release inside a cancelled scope. The release can be cancelled before it completes, retaining concurrency capacity until expiry and temporarily blocking further requests.

**Evidence:** Reproduced with the real Starlette StreamingResponse disconnect path and a limiter whose release reaches an async cancellation checkpoint: release did not complete. Installed Uvicorn uses ASGI HTTP 2.3, which follows this cancellation-scope path.

**Recommended correction:** Shield essential release/refund cleanup with a bounded cancellation-safe scope, preserving the original stream outcome.

### F02 Cancellation during model admission leaves quota charged

**P2 · Unresolved · Earlier FastAPI pass 1**

Location: [controller/conversations_controller.py:329](../../back-end/controller/conversations_controller.py#L329).

Quota is debited before awaiting limiter acquisition, but the acquisition is outside the refund-protected block. Cancellation during the wait consumes quota without executing a model.

**Evidence:** A blocked acquisition was cancelled after quota debit. The usage counter remained one instead of returning to zero.

**Recommended correction:** Cover the complete debit/acquire/stream lifecycle with ownership-aware refund handling, including cancellation before acquisition returns.

### F03 Bulk schema deletion reports success when every deletion fails

### F04 Metrics reset blocks the worker event loop

**P3 · Unresolved · Earlier FastAPI pass 1**

### F05 A second browser tab disconnects the first tab database

**P2 · Unresolved · Earlier FastAPI pass 2**

### F06 Concurrent settings patches overwrite unrelated settings

**P2 · Unresolved · Earlier FastAPI pass 2**

### F12 Database destination validation permits unvalidated Oracle failover hosts

**P1 · Unresolved · Full source review**

Location: [service/database/connection_handlers.py:681](../../back-end/service/database/connection_handlers.py#L681).

Oracle multi-host connection strings are validated using only the first extracted host, then passed intact to the driver. A secondary destination can be loopback/private despite the public-address policy. Related hostname-based paths validate a DNS answer but let the driver resolve the hostname again, leaving a DNS-rebinding window.

**Evidence:** Offline validation/parser probe used u/p@db.example:1521,127.0.0.1:1521/ORCL. Only db.example was validated; the installed Oracle driver parsed both db.example and 127.0.0.1 as destinations. This proves validation bypass, not a live private-network connection.

**Recommended correction:** Parse every effective driver destination, reject unsupported multi-host forms or validate every address, and pin validated destinations where the driver supports it. Recheck all supported DSN grammars.

### F35 Fresh datetime schema-cache entries are treated as stale

**P3 · Unresolved · Full source review**

Location: [service/context/context_service.py:306](../../back-end/service/context/context_service.py#L306).

The datetime/Firestore Timestamp branch converts through datetime.fromtimestamp without a timezone, then subtracts it from an aware UTC datetime. TypeError is caught as a cache miss. **Evidence:** A freshly cached aware datetime returned None with an offset-naive/offset-aware warning; the equivalent ISO-string value was a cache hit.

**Recommended correction:** Normalize all parsed timestamps to aware UTC using fromtimestamp(..., tz=timezone.utc) or astimezone(timezone.utc).
